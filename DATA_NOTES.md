# Nomenclátor data notes

This document records source facts and normalization decisions discovered from
the official Ministerio de Sanidad exports. It is intentionally updated when
the source format changes.

## Source investigated

The canonical public landing page is:

`https://www.sanidad.gob.es/profesionales/nomenclator.do`

The MVP uses the full CSV export linked from that page. The live download URL
is generated by the Ministry's DisplayTag table and is recorded in snapshot
metadata rather than treated as a stable filename.

The two releases examined for the first comparison are:

| Snapshot | Official response date | Records | Transport |
| --- | --- | ---: | --- |
| 2026-07 | 2026-07-16 | 20,521 | Preserved response from the official Ministry URL, retrieved through Common Crawl |
| 2026-08 | 2026-08-09 | 20,559 | Live official Ministry URL |

The July response identifies its original filename as
`20260716_Nomenclator_de_Facturacion.csv`. The preserved HTTP response targets
the same `sanidad.gob.es` export URL as the live collector. Common Crawl is the
archive transport, not the data authority.

The Ministry endpoint is mutable. It returns the current release without a
month in the URL. A collection must therefore archive the bytes immediately,
record the SHA-256 digest, and never overwrite an existing artifact. Localized
landing pages can temporarily show different nominal months while their export
links resolve to the same current artifact.

## Exact CSV format

- UTF-8 text, comma-delimited, with a single header row.
- Python's standard `csv` parser is sufficient.
- 20 columns, listed below in source order.
- Código Nacional is supplied as text and is unique in both inspected files.
- Blank cells are common and meaningful; they are normalized to JSON `null`.
- Dates are strings in `DD/MM/YYYY` form.
- Prices are decimal strings using a dot separator. They must not be parsed as
  binary floating-point values.
- Boolean-like official values use `SI` and `NO`.
- The export mixes medicines, extemporaneous formulations, and financed health
  products. Medicine-only fields are blank for many health-product rows.

labels contain spelling inconsistencies (`homogéna`, `homegénea`, `productor`).
The CSV labels above are the canonical parser inputs. Header aliases are kept in
one mapping rather than scattered through the code.

## Canonical normalized schema

The presentation identity is `codigo_nacional`. A normalized product contains:

- `codigo_nacional`
- `medicine_name`
- `drug_type`
- `generic_product_name`
- `laboratory`: `code`, `name`
- `status`
- `listed_from`, `listed_until` (ISO dates)
- `contribution`
- `active_ingredients` (sorted list)
- `prices`: `retail_with_vat`, `reference`, `homogeneous_group_minimum`
- `homogeneous_group`: `code`, `name`
- `flags`: `hospital_diagnosis`, `long_term_treatment`,
  `special_medical_control`, `orphan_medicine`
- `source_snapshot`
- `source_row`

Names are not split heuristically into a medicine and presentation. The
official `Nombre del producto farmacéutico` is preserved as one field because
the source provides no separate presentation column.

## Normalization decisions

- Strip leading/trailing whitespace and collapse repeated whitespace.
- Convert blank strings to `null`.
- Require a six-digit numeric Código Nacional. Do not invent identifiers.
- Convert source dates to ISO `YYYY-MM-DD`.
- Canonicalize prices with `Decimal`, preserving exact decimal meaning as
  strings and removing insignificant trailing zeroes.
- Convert `SI`/`NO` to booleans; preserve unknown non-empty flag values and
  raise a warning rather than guessing.
- Split active ingredients on commas, trim them, deduplicate them, and sort
  them for comparison because order has no declared meaning in the export.
  The original source row remains traceable through the archived artifact.
- Preserve capitalization. Case-only changes are not currently suppressed.

The ingredient ordering rule is material: the raw July-to-August comparison
reports 968 ingredient changes, while 966 are only reordered values. Two are
genuine changes and remain visible.

## Known limitations

- The public endpoint exposes the current release and does not provide an
  obvious official historical-download index.
- The nominal month must be supplied by the operator and checked against the
  landing-page heading and response date.
- Product removal means absence from the next inspected export. The app does
  not infer a clinical or legal reason for that absence.
- `Estado`, listing dates, and removal dates are displayed as independent
  source fields; the project does not reinterpret them as advice.
- Source-format changes must fail validation until this document and the field
  mapping are reviewed.
